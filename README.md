# DieCut Catalog

Сетевая система хранения, поиска и учета вырубных ножей. Windows-клиент работает с центральным Linux-сервером; сервер хранит данные в PostgreSQL и управляет PDF-чертежами.

## Цели проекта

- единый каталог ножей с поиском и фильтрацией по техническим параметрам;
- карточка ножа с чертежом, PDF, статусом и историей изменений;
- учет тиражей и фактической нагрузки каждого ножа;
- создание нового ножа с интерактивным чертежом и генерацией PDF;
- загрузка существующего PDF, извлечение параметров и подтверждение импорта;
- разграничение прав, аудит действий и резервное копирование;
- импорт действующего Excel-каталога и обратный экспорт в Excel.

## Архитектура

```text
Windows-клиент (WPF)
        |
     HTTPS API
        |
Linux Server
  |-- ASP.NET Core API
  |-- PostgreSQL
  +-- PDF-хранилище
```

Клиенты не подключаются к PostgreSQL или общей папке напрямую. Все операции проходят через API, чтобы сервер мог проверять права, целостность данных и вести журнал изменений. PDF хранятся как файлы, а в базе находятся их метаданные, контрольные суммы и связи с ножами.

Подробности: [архитектура](docs/architecture.md) и [план MVP](docs/mvp.md).

## Технологии

- .NET 8, ASP.NET Core;
- Windows desktop-клиент: WPF;
- PostgreSQL;
- Docker Compose для Debian/Ubuntu;
- управляемое файловое хранилище PDF.

## Структура решения

- `DieCutCatalog.Api` — HTTP API и точка запуска сервера;
- `DieCutCatalog.Domain` — бизнес-модель и правила учета;
- `DieCutCatalog.Application` — сценарии приложения и контракты;
- `DieCutCatalog.Infrastructure` — PostgreSQL, файлы, PDF и внешние интеграции;
- `DieCutCatalog.Desktop` — Windows-клиент.

## Локальный запуск

Требуются .NET 8 SDK и Docker.

```powershell
docker compose up -d postgres
dotnet restore
dotnet run --project src/DieCutCatalog.Api
```

API после запуска: `http://localhost:5080`. Проверка состояния: `GET /health`.

Настройки для рабочей среды и пароли не должны попадать в Git. Для production-развертывания используется `compose.production.yaml`, а секреты передаются через серверный файл `.env`.

## Production-развертывание

На Debian/Ubuntu сервере:

```bash
cp .env.example .env
# Заменить POSTGRES_PASSWORD на случайный пароль.
docker-compose -f compose.production.yaml up -d --build
curl http://127.0.0.1:5080/health
```

API привязан к loopback-интерфейсу сервера. Внешний доступ должен публиковаться только через HTTPS reverse proxy. PostgreSQL доступен исключительно внутри Docker-сети.

## Учётные записи сотрудников

Администратор создаёт сотрудника по электронной почте. Сервер генерирует стойкий временный пароль, сохраняет только его хеш и отправляет пароль через SMTP. При первом входе любые изменения, кроме смены временного пароля, блокируются.

После входа сотрудник может:

- изменить имя, должность, телефон и дополнительные контакты;
- загрузить фотографию JPEG, PNG или WebP размером до 5 МБ;
- изменить пароль с подтверждением текущего;
- изменить адрес электронной почты с подтверждением текущего пароля.

Первый администратор создаётся однократно через `POST /api/setup/administrator` с заголовком `X-Setup-Token`. После создания первой учётной записи этот endpoint автоматически перестаёт работать. Для отправки приглашений обязательны `SMTP_*` параметры из `.env.example`.
## Статус

Проект находится на этапе архитектурного каркаса. Первая версия должна обеспечить каталог, карточку ножа, учет тиражей, загрузку PDF и пользователей. Генератор чертежей и автоматическое распознавание PDF запланированы после стабилизации основной модели данных.
