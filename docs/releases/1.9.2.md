# DieCut Catalog 1.9.2

Версия 1.9.2 исправляет обновление существующих операторских учётных записей после переименования технической роли `Employee` в `Operator`.

## Причина

Роль сотрудника хранится в PostgreSQL строкой. Поэтому сохранённое значение `Employee` нельзя преобразовать в новый enum только за счёт сохранения числового значения `0`.

## Исправление

- data migration заменяет `employees."Role" = 'Employee'` на `Operator`;
- обратная миграция восстанавливает значение `Employee`;
- записи `Administrator` не изменяются;
- добавлен PostgreSQL upgrade integration test с реальной цепочкой миграций, чтением сотрудника и входом по паролю.

## Справочники

- копирование, перенос и дублирование сохраняют технологическую статью `ArticleRtf`;
- архивное состояние сохраняется при переносе между пользовательскими справочниками;
- Move выполняется сервером атомарно: целевая сущность полностью сохраняется до удаления источника, а оба этапа входят в одну транзакцию PostgreSQL;
- при невозможности удалить источник целевая позиция не создаётся.
- Desktop выполняет Copy/Move одним запросом `POST /api/catalog-administration/positions/transfer` и не пытается имитировать rollback сетевыми запросами;
- сервер сохраняет событие Copy/Move с сотрудником и исходным/целевым разделами в той же транзакции;
- события операций со справочниками отображаются в общем журнале и экспортируются в CSV/PDF.
- архивный пользовательский справочник доступен только для чтения: сервер отклоняет любые изменения значений и статей, CSV-импорт, Copy в архив и Move с удалением источника из архива;
- для изменения содержимого администратор должен сначала восстановить справочник; отклонённая операция не оставляет частичных данных или события аудита.

## Excel-импорт

- удалённые ножи не участвуют в сопоставлении импортируемых строк;
- повторно использованный номер корректно сопоставляется с действующим ножом, даже если в истории осталась запись `Deleted` с тем же оборудованием и номером.

## RBAC и Danger Zone

- выбрана классическая модель RBAC вместо неявного dual control;
- оператор не может инициировать опасное действие, даже если знает пароль администратора;
- текущий администратор подтверждает операцию только собственным паролем;
- идентификатор инициатора в журнале ножа больше не подменяется владельцем введённого пароля;
- тесты отклоняют пароль другого администратора и попытку оператора подтвердить Danger Zone.

## Универсальный административный аудит

- добавлена сущность `AuditEvent` с инициатором, необязательным подтверждающим администратором, типом и ID объекта, действием, JSON-снимками до/после и correlation ID;
- журналируются создание и удаление групп, создание/изменение/архивирование справочников, добавление/изменение/удаление значений, переименование системных материалов, фигур и оборудования, CSV-импорт, изменение `ArticleRtf`, Copy и Move;
- событие сохраняется вместе с изменяемыми данными; неуспешный Move откатывает и целевую запись, и аудит;
- общий журнал, поиск и экспорт CSV/PDF включают административные события; CSV дополнительно содержит actor/approver, entity, correlation ID и полные снимки;
- миграция сохраняет ранее накопленные события Copy/Move из `reference_position_events`;
- добавлены unit-тесты полного набора административных операций и PostgreSQL upgrade integration test переноса старого аудита.

## Безопасная генерация фигур

- удалён небезопасный fallback, который рисовал любую фигуру, кроме круга, прямоугольником;
- параметрическая генерация разрешена только для прямоугольника, корректного квадрата и круга;
- круг и квадрат требуют одинаковых размеров L и B;
- для специальной формы, перфорации и неизвестных пользовательских фигур сервер требует загрузить утверждённый PDF с реальным контуром;
- Windows-клиент заранее отключает кнопку **Создать PDF**, показывает причину и оставляет доступной кнопку **Загрузить**;
- отклонённая генерация не создаёт файл, документ или событие «PDF сформирован»;
- добавлены регрессионные тесты всех поддерживаемых и неподдерживаемых типов фигур.

## Обновление

Сервер при запуске применяет миграцию автоматически. Перед обновлением production-сервера рекомендуется создать резервную копию PostgreSQL. Windows-клиент и сервер следует обновить согласованно до 1.9.2.
