# DieCut Catalog 1.9.2

Версия 1.9.2 исправляет обновление существующих операторских учётных записей после переименования технической роли `Employee` в `Operator`.

## Причина

Роль сотрудника хранится в PostgreSQL строкой. Поэтому сохранённое значение `Employee` нельзя преобразовать в новый enum только за счёт сохранения числового значения `0`.

## Исправление

- data migration заменяет `employees."Role" = 'Employee'` на `Operator`;
- обратная миграция восстанавливает значение `Employee`;
- записи `Administrator` не изменяются;
- добавлен PostgreSQL upgrade integration test с реальной цепочкой миграций, чтением сотрудника и входом по паролю.

## Справочники

- копирование, перенос и дублирование сохраняют технологическую статью `ArticleRtf`;
- архивное состояние сохраняется при переносе между пользовательскими справочниками;
- Move выполняется сервером атомарно: целевая сущность полностью сохраняется до удаления источника, а оба этапа входят в одну транзакцию PostgreSQL;
- при невозможности удалить источник целевая позиция не создаётся.
- Desktop выполняет Copy/Move одним запросом `POST /api/catalog-administration/positions/transfer` и не пытается имитировать rollback сетевыми запросами;
- сервер сохраняет событие Copy/Move с сотрудником и исходным/целевым разделами в той же транзакции;
- события операций со справочниками отображаются в общем журнале и экспортируются в CSV/PDF.

## Excel-импорт

- удалённые ножи не участвуют в сопоставлении импортируемых строк;
- повторно использованный номер корректно сопоставляется с действующим ножом, даже если в истории осталась запись `Deleted` с тем же оборудованием и номером.

## Обновление

Сервер при запуске применяет миграцию автоматически. Перед обновлением production-сервера рекомендуется создать резервную копию PostgreSQL. Windows-клиент и сервер следует обновить согласованно до 1.9.2.
