# Обновления клиентского приложения

## Как это работает

После успешного входа клиент запрашивает у сервера `GET /api/updates/latest`. Если опубликованная версия новее установленной, приложение показывает сообщение с номером релиза и описанием изменений. Ручная проверка доступна по кнопке **Check updates** внизу бокового меню.

Архив скачивается с того же сервера, который указан на экране входа. Перед установкой клиент проверяет размер и SHA-256. При несовпадении файл удаляется и установка не предлагается.

Начиная с версии 1.5.0 обновление выполняется пошагово. Пользователь подтверждает загрузку, видит процент, объём и может отменить скачивание. После проверки пакета клиент отдельно запрашивает разрешение на установку. `DieCutCatalog.Updater.exe` показывает этапы резервного копирования и замены файлов, перезапускает клиент, после чего приложение сообщает об успешном обновлении. При ошибке выполняется откат, а журнал сохраняется в `%LOCALAPPDATA%\DieCutCatalog\Logs`.

После первого входа клиент хранит сессионный токен в зашифрованном Windows DPAPI-хранилище. При обычных запусках пароль повторно не запрашивается. После установки новой версии требуется один вход, а кнопка выхода удаляет сохранённую сессию.

Переход с версии 1.3.0 или более ранней на 1.4.0 необходимо выполнить вручную один раз, поскольку в старом клиенте updater ещё отсутствует. Все последующие обновления устанавливаются автоматически.

Из-за ошибки блокировки ZIP в клиентах 1.6.0–1.6.1 переход на 1.6.2 также выполняется вручную один раз. Начиная с 1.6.2 пакет сохраняется после закрытия потока проверки, каждая попытка изолирована в отдельном каталоге, а временные блокировки файлов автоматически повторяются.

## Публикация обновления

1. Увеличьте версию в `Directory.Build.props`.
2. Соберите self-contained клиент и ZIP-архив.
3. Опубликуйте архив на сервере:

```powershell
./scripts/Build-ClientRelease.ps1 -Version 1.9.4

./scripts/Publish-ClientUpdate.ps1 `
  -Version 1.9.4 `
  -PackagePath ./artifacts/release/DieCutCatalog-1.9.4-win-x64.zip `
  -ReleaseName "DieCut Catalog 1.9.4" `
  -Notes "Единый ресурс 500 000 оборотов и нормализация текущих счётчиков"
```

Скрипт вычисляет SHA-256, загружает архив и только после успешной загрузки атомарно заменяет `latest.json`. Поэтому клиент не увидит незавершённую публикацию.

При другом сервере или расположении Docker volume передайте `-Server`, `-IdentityFile` и `-RemoteRoot` явно. Пароли и SSH-ключи в репозитории не хранятся.

## Серверные файлы

API читает обновления из `<Storage:RootPath>/updates`. В production это Docker volume `document-storage`. Активная публикация состоит из:

- `latest.json` — версия, название релиза, дата, имя ZIP, размер, SHA-256 и примечания;
- ZIP-архив клиента — файл, указанный в манифесте.

Если манифест отсутствует, повреждён, ссылается на отсутствующий файл или размер не совпадает, сервер отвечает, что обновлений нет.
