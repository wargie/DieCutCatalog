# Архитектура

## Компоненты

### Desktop-клиент

Windows-приложение предоставляет каталог в табличном виде, карточки ножей, формы учета тиражей, импорт PDF и редактор нового ножа. Для чтения ранее открытых записей допускается локальный кэш. Изменения при отсутствии связи с сервером в первой версии запрещены, чтобы избежать конфликтов.

### API

ASP.NET Core API является единственной точкой доступа к данным и файлам. Он отвечает за аутентификацию, права, валидацию, нумерацию ножей, аудит, импорт и выдачу PDF.

### PostgreSQL

Основные сущности:

- `DieCut` — нож и его технические параметры;
- `Equipment` — оборудование и правила нумерации;
- `ProductionRun` — тираж, материал, заказ, машина, оператор и дата;
- `Document` — PDF, версия, контрольная сумма и расположение;
- `User` и `Role` — пользователи и права;
- `AuditEvent` — журнал изменений.

Количество изготовленной продукции не хранится одним изменяемым числом. Оно вычисляется из записей тиражей, поэтому сохраняется полная история.

### Файловое хранилище

PDF размещаются на сервере в управляемой структуре каталогов. Пользовательское имя сохраняется в метаданных, а физическое имя формируется системой. Замена документа создает новую версию, а не перезаписывает предыдущую.

## Надежность

- ежедневный дамп PostgreSQL;
- отдельная резервная копия PDF;
- хранение копии вне системного диска сервера;
- контрольные суммы документов;
- журнал всех изменяющих операций;
- проверка восстановления резервной копии по расписанию.

## Безопасность

Доступ к API выполняется по HTTPS. Роли первой версии: администратор, технолог, оператор и просмотр. Секреты передаются через переменные окружения и не хранятся в репозитории.

## Учётные записи

Логином является нормализованный адрес электронной почты. Пароли хешируются стандартным ASP.NET Core `PasswordHasher`; открытый пароль не сохраняется. При создании сотрудника сервер генерирует временный пароль и передаёт его только SMTP-сервису. Если письмо не отправлено, создание учётной записи откатывается.

Сессия представлена случайным 256-битным bearer-токеном. В PostgreSQL хранится только SHA-256 хеш токена и срок действия. После смены пароля остальные активные сессии отзываются. Фотографии хранятся в управляемом файловом хранилище, а база содержит только относительный путь.
