# Архитектура

## Компоненты

### Desktop-клиент

Windows-приложение предоставляет каталог в табличном виде, карточки ножей, формы учета тиражей, импорт PDF и редактор нового ножа. Для чтения ранее открытых записей допускается локальный кэш. Изменения при отсутствии связи с сервером в первой версии запрещены, чтобы избежать конфликтов.

### Mobile-клиент

Android-приложение .NET MAUI использует те же HTTPS endpoints и учётные записи, что Windows-клиент. Оно предоставляет операционный поднабор функций: просмотр каталога и карточек, фильтрацию оборудования, ввод тиража или пробега и личный профиль. Мобильный клиент не имеет отдельной базы и не выполняет окончательные производственные расчёты локально: API повторно валидирует входные данные, рассчитывает взаимосвязанные значения и записывает событие аудита.

### API

ASP.NET Core API является единственной точкой доступа к данным и файлам. Он отвечает за аутентификацию, права, валидацию, нумерацию ножей, аудит, импорт и выдачу PDF.

### PostgreSQL

Основные сущности:

- `DieCut` — нож и его технические параметры;
- `Equipment` — оборудование и правила нумерации;
- `DieCutEvent` — события тиража, сброса счётчиков и списания;
- `DieCutDocument` — версия PDF, источник, контрольная сумма и расположение;
- `CatalogReferenceEntry` и `Equipment` — системные значения материалов, фигур и оборудования с форматированной статьёй `ArticleRtf`;
- `ReferenceDirectoryGroup`, `ReferenceDirectory` и `ReferenceDirectoryValue` — пользовательские группы, списки и значения со статьями;
- `Employee` и `UserSession` — сотрудники, роли и серверные сессии.
- `AuditEvent` — универсальный аудит административных изменений с инициатором, необязательным подтверждающим администратором, объектом, действием, JSON-снимками до/после и correlation ID.

Текущие счётчики тиража, пробега и оборотов хранятся в карточке для быстрого каталога, а каждое изменение фиксируется отдельным событием с предыдущими и новыми значениями. Единый интервал до обязательной проверки составляет 500 000 оборотов. Миграция версии 1.9.4 обнуляет только текущие счётчики и нормализует порог; пожизненные показатели, статусы и события сохраняются.

Административный API `/api/catalog-administration` предоставляет CRUD системных значений, групп, справочников и их значений, пакетный импорт, хранение статей и экспорт аудита. Создание, изменение, CSV-импорт, обновление `ArticleRtf`, архивирование, восстановление, копирование, перенос и удаление записывают `AuditEvent` в том же unit of work, что и изменение данных. Copy/Move выполняется единым серверным use case через `/positions/transfer`; для Move создание полной целевой записи, удаление исходной и запись аудиторского события входят в одну PostgreSQL-транзакцию. Desktop не выполняет компенсирующие сетевые удаления. Содержимое архивного пользовательского справочника неизменяемо на уровне сервиса: единый guard используется всеми write-операциями, запрещает Copy в архив и Move из архива и требует сначала восстановить справочник. Изменяющие операции доступны администраторам; удаление группы дополнительно требует пароль администратора. Статьи хранятся в RTF, поэтому WPF-клиент сохраняет форматирование без выполнения HTML или сценариев.

`AuditEvent` хранит `OccurredAt`, `ActorEmployeeId`, необязательный `ApproverEmployeeId`, `EntityType`, `EntityId`, `Action`, `BeforeJson`, `AfterJson` и `CorrelationId`. Для Danger Zone инициатор и подтверждающий администратор фиксируются раздельно. Общий журнал объединяет эти записи с `DieCutEvent` и `EmployeeAccessEvent`; расширенный CSV содержит полные JSON-снимки. Миграция `AddUniversalAuditEvents` переносит накопленные события Copy/Move из `reference_position_events` перед удалением старой таблицы.

Миграция `AddReferenceValueArticles` добавляет статьи к системным и пользовательским значениям. Клиент версии 1.9.0 и API должны обновляться согласованно: старый сервер ответит 404 на маршруты статей и удаления групп.

### Файловое хранилище

PDF размещаются на сервере в управляемой структуре `die-cuts/{id}/`. Пользовательское имя сохраняется в метаданных, а физическое имя формируется UUID. Загрузка и генерация создают новую версию, не перезаписывая предыдущую. Перед импортом сервер извлекает текст и анализирует повторяющиеся векторные контуры; распознанные данные обязательно подтверждаются в карточке.

Параметрический генератор использует строгую классификацию контуров: прямоугольник и квадрат строятся как прямоугольный контур, круг — как окружность. Для круга и квадрата сервер требует равенства L и B. `специальная форма`, `перфорация` и неизвестные пользовательские фигуры не имеют достаточного набора геометрических параметров, поэтому сервер отклоняет их автоматическую генерацию и требует загрузить утверждённый PDF. Неизвестная фигура никогда не преобразуется в прямоугольник по умолчанию.

## Надежность

- ежедневный дамп PostgreSQL;
- отдельная резервная копия PDF;
- хранение копии вне системного диска сервера;
- контрольные суммы документов;
- журнал всех изменяющих операций;
- проверка восстановления резервной копии по расписанию.

## Безопасность

Доступ к API выполняется по HTTPS. В системе используются только две роли: **оператор** и **администратор**. Отдельных ролей технолога и пользователя только для просмотра нет. Секреты передаются через переменные окружения и не хранятся в репозитории.

### Матрица прав

| Возможность | Оператор | Администратор |
| --- | :---: | :---: |
| Просмотр каталога, карточек, PDF, истории ножей и общего журнала | Да | Да |
| Ввод тиража или пробега | Да | Да |
| Создание и редактирование карточек, загрузка и генерация PDF | Да | Да |
| Просмотр справочников | Да | Да |
| Добавление и изменение справочников | Нет | Да |
| Импорт Excel | Нет | Да |
| Установка нового ножа, списание и удаление ножа | Нет | Да, с подтверждением паролем администратора |
| Просмотр справочника сотрудников и удаление сотрудника | Нет | Да, с подтверждением паролем администратора |
| Создание операторов и администраторов | Нет | Да |

Операции административной зоны проверяются сервером. Скрытие кнопки в Windows-клиенте не считается средством авторизации. Для **Danger Zone** используется классический RBAC: текущая сессия должна принадлежать администратору, временный пароль должен быть заменён, а подтверждение проверяется только по собственному паролю этого же администратора. Пароль другой административной учётной записи не делегирует права оператору и не подменяет инициатора аудита.

## Учётные записи

Логином является нормализованный адрес электронной почты. Пароли хешируются стандартным ASP.NET Core `PasswordHasher`; открытый пароль не сохраняется. При создании сотрудника сервер генерирует временный пароль и передаёт его только SMTP-сервису. Если письмо не отправлено, создание учётной записи откатывается.

Сессия представлена случайным 256-битным bearer-токеном. В PostgreSQL хранится только SHA-256 хеш токена и срок действия. После смены пароля остальные активные сессии отзываются. Фотографии хранятся в управляемом файловом хранилище, а база содержит только относительный путь.
