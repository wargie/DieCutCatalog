# Архитектура

## Компоненты

### Desktop-клиент

Windows-приложение предоставляет каталог в табличном виде, карточки ножей, формы учета тиражей, импорт PDF и редактор нового ножа. Для чтения ранее открытых записей допускается локальный кэш. Изменения при отсутствии связи с сервером в первой версии запрещены, чтобы избежать конфликтов.

### Mobile-клиент

Android-приложение .NET MAUI использует те же HTTPS endpoints и учётные записи, что Windows-клиент. Оно предоставляет операционный поднабор функций: просмотр каталога и карточек, фильтрацию оборудования, ввод тиража или пробега и личный профиль. Мобильный клиент не имеет отдельной базы и не выполняет окончательные производственные расчёты локально: API повторно валидирует входные данные, рассчитывает взаимосвязанные значения и записывает событие аудита.

### API

ASP.NET Core API является единственной точкой доступа к данным и файлам. Он отвечает за аутентификацию, права, валидацию, нумерацию ножей, аудит, импорт и выдачу PDF.

### PostgreSQL

Основные сущности:

- `DieCut` — нож и его технические параметры;
- `Equipment` — оборудование и правила нумерации;
- `DieCutEvent` — события тиража, сброса счётчиков и списания;
- `DieCutDocument` — версия PDF, источник, контрольная сумма и расположение;
- `CatalogReferenceEntry` и `Equipment` — системные значения материалов, фигур и оборудования с форматированной статьёй `ArticleRtf`;
- `ReferenceDirectoryGroup`, `ReferenceDirectory` и `ReferenceDirectoryValue` — пользовательские группы, списки и значения со статьями;
- `Employee` и `UserSession` — сотрудники, роли и серверные сессии.

Текущие счётчики тиража, пробега и оборотов хранятся в карточке для быстрого каталога, а каждое изменение фиксируется отдельным событием с предыдущими и новыми значениями.

Административный API `/api/catalog-administration` предоставляет CRUD системных значений, групп, справочников и их значений, пакетный импорт, хранение статей и экспорт аудита. Изменяющие операции доступны администраторам; удаление группы дополнительно требует пароль администратора. Статьи хранятся в RTF, поэтому WPF-клиент сохраняет форматирование без выполнения HTML или сценариев.

Миграция `AddReferenceValueArticles` добавляет статьи к системным и пользовательским значениям. Клиент версии 1.9.0 и API должны обновляться согласованно: старый сервер ответит 404 на маршруты статей и удаления групп.

### Файловое хранилище

PDF размещаются на сервере в управляемой структуре `die-cuts/{id}/`. Пользовательское имя сохраняется в метаданных, а физическое имя формируется UUID. Загрузка и генерация создают новую версию, не перезаписывая предыдущую. Перед импортом сервер извлекает текст и анализирует повторяющиеся векторные контуры; распознанные данные обязательно подтверждаются в карточке.

## Надежность

- ежедневный дамп PostgreSQL;
- отдельная резервная копия PDF;
- хранение копии вне системного диска сервера;
- контрольные суммы документов;
- журнал всех изменяющих операций;
- проверка восстановления резервной копии по расписанию.

## Безопасность

Доступ к API выполняется по HTTPS. Роли первой версии: администратор, технолог, оператор и просмотр. Секреты передаются через переменные окружения и не хранятся в репозитории.

## Учётные записи

Логином является нормализованный адрес электронной почты. Пароли хешируются стандартным ASP.NET Core `PasswordHasher`; открытый пароль не сохраняется. При создании сотрудника сервер генерирует временный пароль и передаёт его только SMTP-сервису. Если письмо не отправлено, создание учётной записи откатывается.

Сессия представлена случайным 256-битным bearer-токеном. В PostgreSQL хранится только SHA-256 хеш токена и срок действия. После смены пароля остальные активные сессии отзываются. Фотографии хранятся в управляемом файловом хранилище, а база содержит только относительный путь.
